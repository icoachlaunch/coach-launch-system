Coach Launch · Slide Mold Library

These are the twenty slide designs your deck is built from. Every slide you present is one of these, with your words in it.

How to use this page

You don't have to do anything with it. When you build a deck, the builder picks the right design for each beat automatically — you never choose from this list slide by slide.

It's here so you can see what's available. Scroll through, get a feel for the shapes, and if you ever want a particular slide to look different, you'll know what to ask for.

To ask for one by name, just say it in plain English:

“Make slide 12 a side-by-side comparison instead.”
“Put the pricing on the big-number design.”
“Use the timeline layout for the Tour.”

What you're looking at

Each design is shown three times — light, dark, and in your accent colour. Same design, three moods. Which one a slide uses is decided by the plan table, so your deck alternates instead of going flat.

The grey tag next to a name tells you how much it holds — “max 5 per column”, “exactly 3”, “one line only”. If your copy runs longer than that, the builder stops and shows you rather than shrinking your words to fit. You then trim it in your Script, and it rebuilds that slide.

Every design can take a background image, and none of them need one. See image-prompts.md if you want to add one.

The grey text under each name is a note for the builder. You can ignore it.

Technical notes — for the builder

You can stop reading here. This part is written for the AI that assembles your deck, so that it clones these designs exactly rather than inventing its own.

  1. Match on data-type exactly. Never fuzzy-match a display label. Copy the matched block's text verbatim — it is the whole document.
  2. Set the surface from the plan table's Surf column: <html data-surface="L|D|A">. One mold, three surfaces. Never restyle to fake a surface.
  3. Fill only data-slot elements, matching by attribute — never by guessing at placeholder wording. Delete surplus data-slot="item" elements; never leave placeholder text.
  4. Auto-brand overwrites only the CL-THEME-TOKENS block — byte-identical in all twenty molds. Nothing else in the CSS is ever touched.
  5. Respect data-max. Overflow is a STOP, not a trim — the copy goes back to the Script.
  6. Set data-cells on the ELEMENT only. The same token appears inside the stylesheet's selectors (.grid[data-cells="9"]), so a blind find-and-replace rewrites the CSS and the grid silently renders the wrong column count. Anchor the edit to the opening tag. Same care with data-surface: it belongs on <html>, and the CSS matches it unquoted, so only ever change the quoted attribute.
  7. Delete every surplus item, then scan for leftovers. After filling a repeater, search the finished slide for the mold's own placeholder words — Item, Title, Name, The step, Supporting line, $0,000. A stale item left behind still renders, and it renders as if it were the client's copy. Fill a slot by replacing the element's whole content: matching to the first </ strands the tail of any placeholder containing nested markup.
  8. Every mold has a bg layer, so an image can go behind ANY slide. Set a background-image on it; the veil over it is a theme token that adapts to the surface, so it works under dark text as well as light. Delete the element when no image is supplied — that is the normal case, and it must never render as an empty box.
