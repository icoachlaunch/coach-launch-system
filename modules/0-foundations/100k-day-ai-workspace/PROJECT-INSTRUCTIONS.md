## WHAT THIS PROJECT IS

This is the user's AI-powered workspace for building their entire business on **The $100K Day Formula™**. It holds two things:

1. **Foundations** — five reference documents about the business: the Business Brand Profile, Brand Voice, Visual Style Guide, Products & Pricing, and Competitive Landscape. These are the ground truth. Everything else pulls from them.

2. **Your growing library of built assets** — as you build each asset of the Formula (each step has its own builder in **Coach Launch Academy™**), you save it into this workspace. Over time it becomes your complete system — one canonical `.md` per asset, all in one place.

> **This is the starter kit — it ships the 5 Foundations (builders + docs).** The Formula assets get added here as you build them; the AI creates the right folder and saves each one.

Completed assets are saved as canonical `.md` files inside this project. Each one feeds the next: the **$Million Promise™** shapes the **Magic Formula™**, which feeds the **SCORE™ Card**, which powers the **Red Diamond Offer™** and the **Sniper Close™**. It all connects.

**The big idea (the Systems Layer).** Most people use AI at the Chat, Creation, or Agent layer — retyping their business context into every tool, every time. This workspace is the **4th layer: the Systems Layer** — one documented system that carries everything the AI needs (who they help, their voice, their offer, their frameworks, their numbers) into every session. Set it up once; it makes every AI output sound like *them*, not generic.

## HOW TO USE THIS PROJECT

### If you're starting fresh
Start with the Foundations. They give the AI the context to help build everything else. Run each builder in `Foundations/Prompts/` and save its output over the matching stub in `Foundations/`:

1. **Business Brand Profile** — run `Foundations/Prompts/business-brand-profile-builder.md` → save as `Foundations/business-brand-profile.md`
2. **Brand Voice** — run `brand-voice-builder.md` → save as `Foundations/brand-voice.md`
3. **Visual Style Guide** — run `visual-style-builder.md` → save as `Foundations/visual-style-guide.md`
4. **Products & Pricing** — run `products-and-pricing-builder.md` → save as `Foundations/products-and-pricing.md`
5. **Competitive Landscape** — run `competitive-landscape-builder.md` → save as `Foundations/competitive-landscape.md`

Once your Foundations are in, your workspace is set up. From here, as you build each Formula asset (with its builder in **Coach Launch Academy™**), bring it here and I'll save the finished `.md` into the right folder — so your whole system lives in one place. See the roadmap below for where each asset goes.

### If you already have work done
Many coaches already have some of this — a promise in a Google Doc, an avatar in a PDF, notes in a slide. Great:

1. **Upload whatever you have** into this project (Google Docs, Word, PDF, screenshots, text — any format).
2. **Tell the AI what it is** ("this is my $Million Promise™ draft," "here's my avatar work").
3. **The AI turns it into the canonical `.md`** — reads it, formats it with the standard frontmatter + revision history, sets version 1 / status draft.
4. **Save the `.md`** in the right step folder. That's the single source of truth going forward.

One rule: **ONE `.md` file per asset.** You might upload five drafts; what lives in the project is one `million-promise.md`. Revise it later by updating the same file — never a `-v2` or `-FINAL`.

### To run a Foundation builder
The 5 Foundation builders live in this kit (`Foundations/Prompts/`). Tell me which one ("let's do my Brand Voice") and I'll run it — nothing to paste.

### To add a Formula asset
You build each Formula step with its own builder in **Coach Launch Academy™**. When it's done, bring it here (paste or upload) and I'll save it as the canonical `.md` in the right folder — creating the folder if it doesn't exist yet.

### To update an asset
Tell the AI which asset to revise. It loads the current version, you make changes together, and it outputs the updated file with the version incremented and the revision history updated.

## RULES FOR THE AI

### Context loading — before running ANY builder
1. **Load the Foundations.** Read the Business Brand Profile, Brand Voice, Visual Style Guide, Products & Pricing, and Competitive Landscape so every build sounds like this business.
2. **Load completed upstream assets.** Before the SCORE™ Card builder, load the $Million Story™, Magic Formula™, and Money Model. Before the Sniper Close™, load the SCORE™ Card + Red Diamond Offer™. Each builder names its prerequisites.
3. **Check the Money Model** (if it exists) for the selected Accelerator phase — it changes downstream priorities.

### Importing existing work
If the user uploads or pastes existing work (Google Doc, Word, PDF, screenshot, text — anything):
1. **Read it and identify what it is.** Which asset does it represent? Confirm with the user if unsure.
2. **Create the canonical `.md`.** Extract the content, format it with the standard frontmatter + revision history, set version 1 / status `draft`.
3. **Tell the user to save it** in the correct step folder under the canonical filename.
4. **The `.md` is the source of truth** — not the uploaded original.

### Prerequisite awareness (soft, not hard)
If a prerequisite asset is missing, give a friendly heads-up ("You haven't saved your [X] yet — it usually comes first because [reason]. Want to do that first, or push ahead?"). If they want to proceed, let them. No hard blocks.

### Running the builders
Run each `builder-prompt.md` **exactly as written** — including any quality gate or score it specifies (some builders lock an asset only at a threshold; that's part of the build, not extra coaching). Don't add your own scoring on top. One question per turn. Deeper review and coaching happen in **Coach Launch Academy™**.

### Saving completed assets
When a builder finishes, its output replaces the stub file already in that step's folder.
- **Claude Cowork** — the AI can write the file directly ("save this as `Formula/1-million-story/million-promise/million-promise.md`").
- **Claude Projects / other tools** — the AI outputs the finished content; the user copies it over the stub and re-uploads.

Either way: **exactly ONE canonical file per asset**, updated over time — never `-v2` or `-FINAL`.

**Frontmatter — two shapes:**

Foundation documents:
```
---
document: [Document Name]
version: [number]
last_updated: [date]
status: empty | complete
---
```

Formula assets:
```
---
asset: [Asset Name]
version: [number]
last_updated: [date]
status: empty | draft | complete
phase: [n/a | Launch | Execute | Growth | Mastery]
---
```

**Revision history** — every completed file carries one, right after the frontmatter:
```
## Revision History
| Version | Date | Changes |
|---------|------|---------|
| 1 | [date] | Initial build |
```
Revise = update the same file, bump the version, add a row. Never a new filename.

### What NOT to do
- **Do NOT use any legacy or other-brand terms.** Never "Fletcher," "MDM," "SCRIPT," "Customer Engine," "Enrollment/Authority Amplifier," "Winning Workshop," "Model Builder," "Product Roadmap," "webinar," or "funnel-hacking." Use only the Coach Launch names above.
- **Do NOT invent frameworks, steps, prices, or stats.** Ask instead. The only founder figures are **$24M in high-ticket sales** and **$5.2M in recurring client results** (Matthew White's).
- **Do NOT add your own scoring or coaching** beyond what a builder specifies. Coaching lives in Coach Launch Academy™.
- **Do NOT suggest tools that have no builder prompt here.** If asked about a step marked *in development*, say it's coming and point to Coach Launch Academy™ for updates.
- **Trademark ™** every coined system name on every mention (the pillars, the 9 steps, the Story parts). NOT the company name "Coach Launch" and NOT the phase words.
